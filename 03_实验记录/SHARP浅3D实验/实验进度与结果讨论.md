```text
一、开始工作前的要求

先进行只读检查，确认：

- 当前实验已经推进到哪个阶段；
- 上一轮实验是否完整结束；
- 输入、配置、脚本版本和结果目录是否对应；
- 是否存在未完成的人工评分、异常记录或结果复核；
- 下一步是否符合既定的单变量实验顺序；
- 当前工作区是否存在与本轮无关的用户修改。

不要因为对话摘要不完整就从头重复实验。应以实验进度记录、配置文件和正式输出为依据恢复上下文。

每轮实验执行前，必须先用通俗语言向我说明：

1. 本轮要解决什么问题；
2. 使用什么输入，会生成什么输出；
3. 为什么当前阶段需要做；
4. 本轮通过后进入哪一步。

可以把它理解为：正式测量前，先说明这次要测什么、用哪把尺子、记录什么结果，以及测完后如何决策。

如果本轮已经在既定方案中得到授权，完成上述说明后可以继续执行；如果涉及改变实验路线、评价标准、冻结参数或扩大实验范围，应先征求我的确认。

二、实验变量控制顺序

必须严格按以下顺序推进，不得同时改变多个变量：

1. 固定完整高斯、0% 裁剪，只改变运动幅度；
2. 冻结运动幅度后，只比较 0%、3%、5%、10% 单边裁剪；
3. 冻结运动和裁剪后，只比较 100%、75%、50%、25% 高斯保留率；
4. 参数冻结后再进行规范化性能测试；
5. 最后使用 10～20 张未参与调参的图片做独立验证。

如果前一阶段尚未通过，不要提前进入后一阶段。不要用裁剪掩盖主体内部的拖影、错误遮挡或反射变形；不要用高斯剪枝结果替代完整高斯条件下的运动幅度判断。

三、指标解释与结论边界

屏幕运动主要报告：

- P95：主要决策指标；
- P99：异常诊断指标；
- 最大值：极端异常诊断指标；
- 同时报告像素值和占实际渲染画宽的比例。

当前高斯投影位移只是屏幕运动的代理指标，不能直接等同于图像特征光流、固定相机旋转角度、真实世界相机平移距离或 Alpha 值。

静止图像质量可报告 PSNR、SSIM、LPIPS，以及 Alpha 掩码区域指标。视频稳定性应结合：

- 相邻帧自动指标；
- 完整 60 帧人工播放；
- 空洞、拉丝、闪烁、纸片感、遮挡错误和反射变形；
- 首次明显伪影帧号；
- 统一的人工质量评分。

自动指标只能辅助筛查，不能代替完整视频人工判断；抽帧检查也不能代替完整播放。冒烟测试、工具校准和少量样本结果只能证明工具链可运行，不能作为最终参数结论。

五、每轮结束后的汇报格式

每完成一轮实验，都按以下结构向我汇报：

1. 本轮做了什么
   - 实际输入、固定变量、改变变量、运行配置和输出位置。
2. 结果如何
   - 完成数量、失败数量、关键指标、人工观察和异常情况；明确区分自动统计、抽帧观察和完整人工播放结果。
3. 能得出什么结论
   - 哪些有充分证据，哪些只是候选判断，哪些暂时不能下结论。
4. 对后续实验有什么影响
   - 是否通过、能否冻结参数、是否需要补跑或复核，以及下一轮应保持和改变哪些变量。
5. 下一步计划
   - 下一轮问题、输入、预计产物、通过标准和通过后进入的阶段。
6. 文件与验证情况
   - 新增或修改的正式脚本、配置和记录；是否覆盖原结果；语法、帧数、分辨率、编码和结果完整性是否通过；仍需哪些人工检查。

八、人工评分阶段专用流程

当实验进展到需要人工播放视频并评分的阶段时，按以下流程操作。

1. 评分文件定位

检查 outputs/03_运动实验/{P01..P05}/{md000..md008_*}/video_manual.json。
每个文件应包含 schema_version: "2.0" 及 13 个评分字段。
如果文件仍是旧版 3 字段模板或不存在，说明评分表尚未升级，应先安全升级空表再开始评分。

2. 判断当前是否处于评分阶段

阅读本文件"## 当前状态"表格：
- 如果阶段 2（运动矩阵）状态为"自动部分已完成"且说明中包含"人工评分待完成"→ 当前处于评分阶段；
- 如果阶段 2 状态为"已完成"且运动幅度已冻结 → 已越过评分阶段，进入裁剪；
- 如果阶段 2 状态为"已完成"但运动幅度显示"待冻结"→ 评分已完成但冻结决策待确认。

3. 评分完整性检查

运行 python scripts/sharp_motion_review_summary.py --check-only。
该脚本会列出每份 video_manual.json 的缺失字段。
如果 20 份全部填完且 overall_quality_score 全部不为空 → 评分完成，可生成正式汇总。
如果有未填项 → 向用户报告缺失列表，等待用户继续填写，不要催促或代替用户打分。
不允许在评分未完成时生成正式汇总（除非用户明确使用 --allow-incomplete）。

4. 评分完成后的冻结流程

运行 python scripts/sharp_motion_review_summary.py 生成汇总。
脚本会自动给出冻结建议（0.04 / 0.02 / 分场景）。
向用户报告：
- 各档最低整体质量分；
- P01 和 P05 在 0.04 下是否通过；
- 冻结建议及依据；
- 是否需要用户确认才能写入冻结配置。
用户确认前不得修改 pilot_manifest.csv、experiment_defaults.json 或进度台账中的运动幅度字段。

5. 评分阶段不做的操作

- 不重新渲染视频；
- 不修改已生成的 MP4、PNG、NPY、CSV 或自动指标 JSON；
- 不提前进入裁剪实验；
- 不将自动指标的优劣等同于人工评分结论；
- 不因为 LPIPS 未安装而中断评分流程（评分只需视频播放器和文本编辑器，不需要 Python 环境）。

6. outputs 目录缺失时的处理

outputs/ 目录不提交 Git。如果新电脑上 outputs/03_运动实验/ 不存在：
- 询问用户是否已通过 U 盘/移动硬盘拷贝 outputs/ 到对应位置；
- 如果用户选择重渲染，使用 scripts/run_motion_matrix.ps1，但必须先在只读检查中确认 sharp 环境、GPU、CUDA、gsplat 和权重均就绪；
- 渲染结果应写入与原始相同命名规则的目录，不要改变 config_name 格式；
- 重渲染后仍需重新生成 motion_results.csv/json（运行 scripts/summarize_motion_matrix.py）。

7. 评分参考文档

评分标准、字段定义和播放顺序详见 03_实验记录/SHARP浅3D实验/运动视频人工评分说明.docx。
自动指标（motion_results.csv）仅供参考，不作为评分依据。

九、逐项引导式人工判断通用原则

当任务包含人工评审、质量验收、故障诊断、问卷填写或多指标决策时，助手应采用逐项引导方式，不要一次性要求用户填写整张表格。

1. 开始前先确认
   - 当前要评审的对象；
   - 评价指标、评分方向和通过标准；
   - 结果需要记录到哪里；
   - 哪些内容必须由用户判断，哪些可以自动计算。

2. 一次只处理一个评价对象
   - 按固定顺序推进；
   - 优先从基线或最容易理解的对象开始；
   - 不同时比较过多对象或改变多个条件。

3. 每个对象开始前简要说明
   - 它在当前任务中的作用；
   - 需要重点观察什么；
   - 它与前一个对象的主要差异；
   - 完成后会影响什么决策。

4. 每次只询问一个评价项
   - 先解释该指标的直观含义；
   - 说明评分方向和各档标准；
   - 给出需要重点观察的位置或现象；
   - 用户可以直接给分，也可以先描述现象。

5. 用户负责最终判断
   - 助手可以根据用户描述提出候选分数或归类建议；
   - 必须明确说明推断依据；
   - 未经用户确认，不得代替用户填写主观评分；
   - 不得用自动指标替代人工判断。

6. 每个对象完成后先汇总
   - 列出已经确认的各项答案；
   - 标出未填写、冲突或不确定内容；
   - 由用户确认后再写入正式记录；
   - 写入后检查格式和字段完整性。

7. 中断后从断点恢复
   - 先读取已有记录和实时进度；
   - 说明已经完成到哪个对象、哪个评价项；
   - 不重复已确认内容；
   - 不覆盖历史判断。

8. 全部完成后再形成结论
   - 先检查所有必填项是否完整；
   - 分开呈现客观数据、用户观察和助手推断；
   - 区分候选结论与正式冻结结论；
   - 涉及参数冻结、路线改变或扩大范围时，等待用户确认。
```

本地文献得到的候选启发：

1. **AnySplat 的可微体素化**：将空间位置接近的像素级高斯按置信度合并；论文报告可去除约 30%～70% 的冗余高斯。可借鉴到 SHARP 输出后的候选合并，但 AnySplat 原任务是多视图前馈重建，不能直接当作单图结果。
2. **ResGS 的 Residual Split**：为需要增密的粗高斯增加缩小的残差高斯，同时降低原高斯不透明度，以兼顾覆盖和细节。可为 Framework 的细结构 Split 提供依据；原论文属于多视图逐场景优化，需要改造成网络预测的拆分参数后才可能用于前馈单图。
3. **AAA-Gaussians 的稳定渲染**：通过 3D 平滑、稳定包围、3D 剔除和排序改进，减少旋转过程中的混叠、Pop-in、Popping 和投影畸变。它主要解决连续运动稳定性，不直接压缩生成模型。
4. **StochasticSplats 的无排序渲染**：采用随机光栅化和 OpenGL 实现，在论文桌面硬件实验中以合理画质获得约 2～4 倍速度提升，并允许通过每像素采样数控制速度/质量。低采样噪声和 TAA 可能引入闪烁或拖影，必须与完整视频人工评分结合验证。
5. **3DGS-LM**：主要减少多视图逐场景优化时间，对 SHARP 单次前馈生成和移动端交互帮助有限。
6. **EVER、RayGaussX**：偏向精确体渲染、光线追踪或光线步进，质量研究价值较高，但当前不宜作为 2K 移动端实时主路线。
7. **RegGS**：主要解决多张无位姿图像的高斯注册，与当前严格单图输入距离较远。

候选 3DGS 优化链路：

`SHARP 基础高斯或轻量学生模型 → 区域/置信度预测 → 可微体素合并 → 细结构 Residual Split → 显露 Spawn → 多视角贡献筛选 → 硬剪枝、相似高斯合并与属性量化 → 稳定移动端光栅化`

结论边界：

- 3DGS 优化可以降低约 118 万高斯带来的文件、驻留内存、排序和光栅化成本，并改善细结构与连续渲染稳定性；
- 它不能单独解决 SHARP 约 2.81 GB 权重及生成网络激活造成的峰值内存，也不能自动保证 2K 端到端生成小于 5 秒；
- 若完整生成阶段要求峰值内存小于 3 GB，部署端不能原样携带当前 FP32 SHARP，仍需蒸馏、轻量骨干、FP16/INT8、低分辨率辅助补全和分阶段释放内存；
- 当前本地文献对自适应增密和渲染稳定性覆盖较好，但对重要性剪枝、向量量化、码本压缩和移动端文件格式覆盖不足，需要继续检索专门的 3DGS 压缩论文。

`文献/02_单图3D照片与分层表达/05_TMPI_Tiled_Multiplane_Images_for_Practical_3D_Photography.pdf`

TMPI 初步定位：

- 输入为单张 RGB 图像和单目深度，输出为由多个局部 MPI 小块组成的 Tiled Multiplane Image；
- 核心思想是利用局部区域深度变化小于全图深度变化的特点，让每个小块只使用少量、自适应放置的深度平面；
- 论文通过置信度加权 K-means 为每个小块选择深度平面，并通过重叠小块和 RGBA 精炼降低块边界伪影；
- 主要实验设置为每块 4 个深度平面、64 像素小块；其目的不是追求完整三维重建，而是降低单图 3D 照片在移动端和 VR 中的计算与存储成本；
- 论文仍存在细结构跨小块不一致、训练渲染复杂和边缘去遮挡依赖裁剪等限制；
- 论文表 2 的运行时间、内存和空间指标来自 RTX 3080 与 350×630 输入，且单目深度开销单独报告，不能直接作为当前移动端小于 5 秒或小于 3 GB 的证据。

与当前 SHARP 实验的关系：

- TMPI 为“压缩 3DGS”之外提供了另一条轻量表示路线，可用于比较 3DGS 和局部分层表示的质量、大小、渲染成本及去遮挡能力；
- TMPI 的局部自适应思想可以启发 SHARP 后续按区域分配高斯预算，而不是全图采用相同保留率；
- TMPI 对图像边缘进行裁剪评价，进一步说明后续文献 Review 必须记录裁剪、掩码和失败样本排除规则；
- TMPI 精读与文献 Review 可以和 SHARP 实验并行，但不改变当前“运动幅度 → 裁剪 → 高斯保留率 → 性能测试 → 独立验证”的正式顺序。
