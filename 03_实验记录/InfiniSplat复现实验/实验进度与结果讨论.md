# InfiniSplat 复现实验：进度与结果讨论

## 1. 文档定位

本文是 InfiniSplat 对照复现分支的实时进度权威入口。自研 Framework 的结果继续记录在 `03_实验记录/自研Framework实验/01_Stage0_1_角度与显露补全/实验进度与结果讨论.md`，跨电脑同步规则见 `03_实验记录/双电脑实验同步与产物管理说明.md`。

当前状态：**官方 P01 RGB 单图 PLY 与官方60帧视频工具链已分别在 `win5060` 和 `linux5080` 跑通；两台机器的自动完整性与完整SHA256已提升到 records，用户完整播放待完成；尚未接入统一 `true_arc` 轨迹，因此不能与 SHARP 或自研 Framework 作正式优劣结论。**

## 2. 研究问题与评价边界

- 第一阶段：验证官方 RGB-only 模式能否在自有 P01 输入和 8 GB GPU 上稳定生成 PLY 与官方演示视频。
- 第二阶段：冻结一份明确哈希的 PLY，适配项目统一的水平总视角 5°/15°/30° `true_arc` 轨迹。
- 正式对比必须统一输入、相机轨迹、分辨率、裁剪、自动指标和人工评分；官方演示轨迹只用于工具链冒烟。
- 论文与项目页报告的 SOTA 属于作者公开结论；在本地统一协议完成前，不写成项目复现结论。

## 3. 冻结源码与环境

- 官方源码路径：`源码/InfiniSplat/`；固定上游 commit：`4146c8683b9bfb7756ddf45bf293093a31848074`；Apache-2.0。
- 独立 Conda 环境：Python 3.10.20、PyTorch 2.9.0+cu128、torchvision 0.24.0+cu128、xformers 0.0.33.post1、gsplat 1.5.3。
- Windows 的 gsplat 1.5.3 使用已记录的 MSVC 兼容补丁：`01_官方RGB单图冒烟/scripts/gsplat_1.5.3_windows_backend.patch`。
- RGB 权重大小为 3,142,241,921 bytes，文件 SHA256 为 `D68A8C99109F06A264567766BD52D8D9BA81E51D044D0A966C3336160EA7007D`。
- P01 输入 SHA256 为 `68EE4C66CDC910673B536AF507F51C757E5325B02139C84585AFE610B0C80DA4`。
- InfiniSplat 环境、权重与编译产物必须和 `sharp` Python 环境隔离；允许只复用机器已有的 CUDA Toolkit。

## 4. 2026-08-09 P01 官方 RGB 冒烟

### 4.1 PLY-only

- 配置：`01_官方RGB单图冒烟/configs/p01_official_rgb_ply_smoke_v1.json`。
- 官方推理成功，产生 1,475,982 个高斯；PLY 为 82,655,790 bytes，SHA256 为 `565D0B17E1F50D8EF682E1AF388ABBBD61DB50A69E458B3F83A0C9F482509AA6`。
- 实测约 12 分 40 秒，抽样显存高点约 7.8/8.15 GB；计时包含模型加载、推理、漂浮过滤和 PLY 导出。

### 4.2 官方视频

- 配置：`01_官方RGB单图冒烟/configs/p01_official_rgb_video_smoke_v1.json`。
- 完整官方 CLI 返回成功；新 PLY 含 1,476,016 个高斯，82,657,694 bytes。它与 PLY-only 相差 34 个高斯，说明重复运行存在轻微非确定性。
- MP4 为 H.264 High、yuv420p、3324×2494、10 FPS、6 秒、60/60 帧，大小 4,715,768 bytes，可完整解码。
- 全流程约 15 分钟，显存抽样高点约 7.83/8.15 GB，未发生 OOM。
- 进度历史中该 PLY 和 MP4 只记录了省略哈希；另一台电脑必须从原文件重新计算完整 SHA256 并写入 `records/`，之后才能冻结和跨机校验。

### 4.3 当前结论

- 已证实官方 RGB 单图工具链能在本项目的 8 GB 级 GPU 环境生成 PLY 与视频。
- 助手联系表抽查提示顶部边界可能有大面积黑色显露区域，右上树冠附近可能有模糊或拉伸；这不是用户完整播放结论。
- 用户尚需完整播放官方 60 帧视频，记录黑边、拉伸/涂抹、漂浮、深度错误、闪烁和主观运动幅度。
- 目前没有统一角度结果，不能宣称 InfiniSplat 优于 SHARP 或自研 Stage 1。

- 固定机器 ID：Windows RTX 5060 Laptop 为 `win5060`，Linux RTX 5080 服务器为 `linux5080`；后续不使用含义会随工作位置变化的“本机/另一台电脑”。
- checkpoint、两份 PLY 和官方 MP4 当前位于产出机器 `win5060`；`linux5080` 是否持有副本以服务器本地核验为准。
- `win5060` 已生成并提升 Git 可同步的 `artifact_manifest.json`、`run_summary.json`、`environment_lock.json` 和 `video_integrity.json`，完整 SHA256 已从原文件重新计算。
- 用户尚未完整播放官方视频，因此 `manual_review.json` 未创建；助手联系表观察不作为人工评分。
- `linux5080` 默认不传输 Windows checkpoint、PLY、MP4 或环境；服务器通过 Git 获取源码、配置、P01 输入和跨平台脚本，重新下载 checkpoint 后重跑官方冒烟。Windows Conda 环境和 gsplat `.pyd` 不得复制到 Linux；只有必须使用同一 SHA256 时才传 PLY。

## 6. 下一步

1. 用户在 `win5060` 完整播放官方 60 帧视频并写入人工评分。
2. `linux5080` 激活独立环境后，使用 `scripts/run_official_rgb_smoke.py` 和相同 P01 配置重跑官方视频冒烟；保存服务器自己的 `run_receipt.json` 和完整 SHA256。
3. 将服务器新生成的 PLY作为冻结候选报告给用户；只有用户明确指定 `linux5080` 和完整SHA256后，才可冻结为 true_arc 适配输入。它是新的复现运行，不冒充 Windows 的 `2AF5F60B...E9E2` PLY。
4. 单独设计 InfiniSplat PLY 到 `true_arc` 5°/15°/30° 的相机坐标与渲染适配器。
5. 统一轨迹与评价协议跑通后，再与 SHARP 和自研 Framework 作同口径比较。
