## 9. 2026-08-12 归因结论（排查闭环）

### 9.1 排查结论

1. **焦距问题不成立**：P01 嵌套 EXIF 含 `FocalLengthIn35mmFilm=27`、`FocalLength=5.52mm`；InfiniSplat 走嵌套 EXIF 读取（`infer_single_image.py:107`），未进入 30mm 默认回退。EXIF 换算焦距 3195.073px（4096 宽）/ 1198.152px（1536×1152 推理）与 SHARP PLY 元数据一致。当前运行已等效显式 `--focal-px 3195.073`，无需重跑；3195px 应称"EXIF 换算焦距"，非独立实测。
2. **官方演示轨迹问题成立（顶部黑洞主因）**：`create_demo_trajectory`（`infer_single_image.py:737`）固定看向高斯中位点 `[-0.0169, -0.9025, 8.4513]`，首帧相对原始相机约 `-6.10°` 俯仰重定向，第一帧外参不是单位矩阵。受控实验证实：官方轨迹首帧顶部即有大块黑洞；原始中心相机中心帧顶部硬空洞率降至 0%。
3. **固定高斯数与黑底：事实成立但因果修正**：固定目标采样约 150 万高斯、漂浮过滤后约 147.6 万；3324×2494 约 0.18 高斯/px 不等于必然覆盖不足（一个高斯覆盖多像素）；黑底只把已有低 Alpha 区域显示为黑，不产生空洞。1536×1152 重渲密度约 0.83 高斯/px 仍被判模糊且不可接受。更准确：1536→3324 放大放大柔糊，但主因是模型生成的高斯本身缺少远处文字、树叶和画面两侧高频细节。

### 9.2 分支决策

- 原始中心相机、推理分辨率 1536×1152、总范围 5° 下仍被明确判为不可接受 → **停止 InfiniSplat 的 15°/30° 正式实验**是合理决策；
- InfiniSplat 不作为项目 30° 解决方案；可借鉴其表面对齐采样与隐式高斯解码结构，纳入表示优化候选；
- 自研 Framework Stage 1（显露补全 + 补充高斯）继续作为 30° 主路径，下一阻塞点仍为二维补全网络质量。

## 11. 2026-08-14 远景模糊的采样密度因果消融

### 11.1 源码机制核对

- 官方配置固定 `sample_point_num=1500000`，但不是简单按屏幕面积均匀放置；约65%预算用于2像素网格锚点和 RGB/深度梯度细节顶点，余下预算用于三角面内部采样；
- 面内采样权重是三角形实际3D面积乘深度系数，远景没有因“投影面积小”而被必然少分配；顶点责任面积与 `depth²/(fx·fy)` 成比，高斯基础尺度也随深度增大，目标是维持屏幕覆盖；
- 因此待验证的更精确假设是：固定预算可能影响覆盖，但远景高频丢失可能更多来自4096→1536双线性缩放、细节顶点优先级和隐式高斯颜色/尺度解码的表示带宽。

### 11.2 既有150万 PLY 的中心投影诊断

- 新增 `scripts/analyze_center_gaussian_density.py`，从 PLY 内嵌单位外参和1198.152 px内参投影1,476,073个高斯，并由四元数、`exp(log-scale)` 和相机 Jacobian 计算1σ屏幕协方差椭圆；
- 1,455,052个高斯中心投影在画面内，约0.822个中心/像素；全局投影主半径中位数约2.10 px；
- 远景 tile 中心密度是近景的92.4%，不存在数量级的远景密度塌缩；25.69–31.82深度分位段反而达到1,362个中心/占用 tile，投影主半径中位数3.40 px；
- 细节保留与中心密度仅弱正相关（Spearman 0.255），而 RGB 误差与 tile 平均深度强正相关（0.685）。这一观测诊断不支持“远景单纯因中心密度过低而模糊”，但尚不是因果证据。

### 11.3 75万/150万/200万单变量消融

- 本地官方 CLI 新增默认关闭的 `--sample-point-num`诊断参数，不传时保持官方行为；最小源码补丁保存在 `patches/infinisplat_sample_point_num_diagnostic_cli.patch`；
- 三档只改请求采样数，共用 P01、RGB checkpoint、1536×1152、相机内外参、floater filter 和0°中心渲染；过滤后高斯数分别为737,321、1,476,073、1,967,701；
- 75万→150万使整体 PSNR 从22.881 dB提升到24.881 dB，硬空洞从2.369%降到0.191%，说明预算过低确实会同时损害覆盖与外观；
- 150万→200万使硬空洞继续下降74.9%（降到0.048%），Alpha≥0.95从95.77%升到98.33%，证明更多高斯能增加覆盖；
- 但200万的整体 PSNR 相比150万反而降低0.191 dB，远景 PSNR 降低0.164 dB，远景细节保留中位数变化仅 `-0.00385`；统一图也显示150万和200万远景视觉差异很小，未恢复原图文字和树叶细节；
- **结论**：采样预算是 Alpha 覆盖的重要因素，但官方150万之后已进入远景细节收益平台。P01 远景模糊的主因不是“高斯总数不足”，更可能是输入降采样与特征/隐式解码器的高频表示带宽。该结论不解冰 InfiniSplat 15°/30°分支，也不把200万改成新默认。

机器可读证据为 `02_true_arc统一协议/records/p01_center_gaussian_density_diagnostic_v1.json`、`p01_sample_budget_comparison_v1.json` 与 `p01_sample_budget_artifact_manifest_v1.json`；大型 PLY、中心帧和统一复核图仅保留在 `linux5080` 的 `outputs/01_诊断对照/`。

## 12. 2026-08-14 官方风格场景与轨迹适用域校准

### 12.1 对论文主张和轨迹的修正理解

- 论文主要研究大基线下高斯是否仍组织为连贯的已有可见表面，特别是大平面和明确物体边界；不能把它等同为对所有新显露区域的生成式补全。
- 论文正式评价使用真实源-目标相机位姿，按米制基线分档，要求视锥重叠超过 60%，并过滤过度旋转和背向视图；这不是项目 `true_arc` 角度轨迹。
- 论文局限章也明确承认：大显露、错误深度先验和极端外推会产生不完整几何、拉伸或幻觉外观。
- 公开 CLI 轨迹是源相机坐标系中的水平横移 `x` + 前后 `z` dolly，`y=0`，并在每帧持续 look-at 有效高斯中位点，并非单纯左右旋转。

### 12.2 三场景统一官方轨迹试验

- 保留 `true_arc` 脚本不变；`render_frozen_ply_official_demo_lowmem.py` 新增语义明确的 `official_orbit_dolly_look_at` 模式别名，与旧 `official_demo` 兼容，并在 `result.json` 写明轨迹公式。
- 在物理 GPU1 上使用同一 1536×1152、60 帧、10 FPS 轨迹分别重渲自有 P01、官方 `eth3d_courtyard.png` 和官方 `scannetpp_fe94fc30cf.JPG`。
- P01 全帧硬空洞率平均 10.80%，顶部 10% 区域平均 97.44%；建筑、草地和树群大体结构可辨识，但高频细节发糊且顶部几乎全程无覆盖。
- ETH3D 全帧硬空洞率平均 11.35%，顶部 10% 平均 99.01%；砖墙、拱窗、长椅和沙发主体形状保持较好，但新显露顶部仍为黑洞，小物体和接缝有模糊/涂抹。
- ScanNet++ 顶部区域明显好于前两者（平均 4.32%），床、墙、地板和衣柜层次较稳定；但全帧硬空洞率仍平均 15.79%，主要分布在左侧近景、底部和视锥边界，杂物有涂抹或丢失。

### 12.3 修正后结论

- 用户对论文的观察成立：**InfiniSplat 在物体边界明确、大平面占主导、源-目标仍高重叠时，对已有表面的形状和连贯性确实表现更好**。
- 更准确的表述是：**它是有明确适用域的表面结构基线，但不能直接解决本项目的大显露生成补全、复杂高频场景和总范围 30° 质量要求**。
- 分支决策不变：InfiniSplat 保留为表面对齐采样和隐式高斯解码的结构参考；自研 Framework 继续承担显露检测、生成式补全和补充高斯的主路线。

机器可读记录为 `02_true_arc统一协议/records/official_style_scene_calibration_v1.json`；三份视频、五个关键帧、Alpha 图和逐帧 CSV 位于 `linux5080` 的 `outputs/01_诊断对照/`，同时已复制到被 Git 忽略的根目录临时 PPT 素材包。

## 13. 2026-08-14 ETH3D 真实相机大基线协议级复现

### 13.1 为什么重做

- 第 12 节运行的是官方公开 CLI 的小幅 Demo 轨迹，三组横移最大值只有约 0.2～0.3 m，不能代表论文 Fig. 3/4 的真实大基线结果；此前“官方轨迹校准”应更准确称为“官方 Demo 小幅展示轨迹校准”。
- 论文正式实验从真实多视图数据中取 source-target 相机位姿，并设置 `[2,+∞)` m 大基线档。作者公开仓库未提供 512 对清单、Fig. 3/4 精确帧号或视锥重叠代码，因此本轮定位为协议级复现，不宣称精确复刻论文某一行。

### 13.2 数据与候选对

- 从 ETH3D 官方下载 `courtyard_dslr_undistorted.7z`：500,990,569 bytes，SHA256=`9DC31263...72BA26D`；包含 38 张 undistorted DSLR 图、4 组 PINHOLE 内参和完整 COLMAP 外参；
- `select_eth3d_large_baseline_pairs.py` 按论文 10 个连续视图窗口枚举 594 个有向候选；因作者未公开重叠实现，本地使用“共享注册稀疏点 / 两帧较小可见点数”作为显式标注的代理；
- 代理门槛 60%、基线至少 2 m、相对旋转不超过 60°时共有 8 个有向候选；首轮冻结 `DSC_0313→DSC_0317`：序列间隔 4、基线 2.587103 m、相对旋转 17.327843°、共享点代理 63.424%。

### 13.3 推理与真实目标相机渲染

- source 推理显式使用 ETH3D `camera_id=1` 的完整 3×3 内参，不使用 EXIF 或 30 mm 回退；关闭 Demo 视频，仅生成 1,476,976 个高斯的冻结 PLY；耗时 53.265 秒，PLY SHA256=`6FB955BC...50C633`；
- 将 COLMAP 世界坐标外参转换为 `source_camera→target_camera` 的真实 W2C，并按论文 ETH3D 尺寸 2016×1344 渲染 RGB、Alpha 和派生法线；
- 首次渲染因非激活 shell 的 `PATH` 未包含已安装 Ninja，在 gsplat JIT 前停止；两张参考图保留。补全 PATH 后 `retry1` 成功，渲染与法线共 77.720 秒；
- 目标硬空洞（Alpha<0.01）46.62%，Alpha≥0.5 覆盖率 50.78%。覆盖区域里的主体墙面、窗框、砖带和大边界保持连贯，但新显露地面、左侧/视锥外区域仍为空，细小物体发生柔化或碎裂。

### 13.4 结论

- 这次视角变化明显，已不再是 Demo 小幅运动；输出构图由正面墙转向真实目标帧的侧向构图，证明外参方向正确。
- 结果更准确地复现了论文所强调的现象：大幅移动后，InfiniSplat 在已有覆盖表面上的结构连贯性较强；白底显示时的画面形态也接近 Fig. 4 的外部表面观察。
- 同时它仍没有补全输入视锥外的新内容。论文使用 frustum-visible mask，当前没有作者未公开的精确 mask，因此本地全画面或覆盖区 PSNR/SSIM均只作诊断，不能与论文 Table 1 横向比较。
- 本结果修正了对 InfiniSplat 的认识，但不改变项目路线：InfiniSplat 适合作为“大基线已有表面组织”参考；自研 Framework 仍需解决显式新显露生成和总范围 30°。
