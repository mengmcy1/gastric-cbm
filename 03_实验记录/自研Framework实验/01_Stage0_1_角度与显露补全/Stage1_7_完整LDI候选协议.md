# Stage 1.7 完整 LDI 候选协议

> 状态：**P01 官方完整 LDI + 冻结 `true_arc` 30°候选 v4 已完成用户评阅并正式不通过：左右端空洞严重度均为3，拉伸/虚假结构严重度2；运动连续性尚可，但总体不通过。停止本候选，不扩展P02/P05、不转补充高斯。**

## 1. 为什么进入本阶段

Stage 1.6 的 source-only 三头网络可以过拟合单样本，却不能在独立验证场景可靠区分“存在遮挡后表面”和“目标视角已验证自由空间”。继续只增加场景或调整优化器没有足够收益，因此本阶段改变信息结构，验证带显式像素连通关系的 Layered Depth Image（LDI，分层深度图）完整链路。

本实验不同于已失败的固定端点3D Photo adapter：旧实验只把官方三个网络套到冻结二维掩码；本实验实际执行官方 `write_ply` 的 LDI 建图、深度边界断开、局部边缘补全、深度补全、颜色补全、第二轮分层补全和 mesh 渲染。

## 2. 冻结输入与唯一协议改动

- P01 原图及 SHA256不变；
- 深度使用已冻结的 P01 中心深度，不调用旧版 MiDaS，以免同时更换深度基础；
- 原始焦距固定为3195.073 px，不使用官方 `max(H,W)` 默认焦距；
- 相机使用项目统一 `true_arc`：总范围30°、端点±15°、圆弧半径5.203962802886963、61帧、30 fps；
- 输出768×576，裁剪为0，不用裁剪隐藏空洞；
- 官方源码固定 commit `de0446740a3726f3de76c32e78b43bd985d987f9`，不直接修改；NumPy、MoviePy和GPU设备兼容放在项目包装脚本。

该实验是“官方完整 LDI 构造 + 项目统一输入/相机适配”，不是官方论文默认 MiDaS、默认焦距和默认平移轨迹的逐项复现。

## 3. 运行与协议检查

- v1 在模型加载前因旧 MoviePy 缺少 `pkg_resources` 退出；
- v2 进入官方边界外推后发现 `gpu_ids` 必须是整数，字符串会把输入留在CPU；
- v3 首次完整生成99,121,190字节 LDI mesh，但圆弧半径误取中心像素深度112.96，且MoviePy产生62帧，只保留为诊断；
- canonical v4复用完全相同SHA256的v3 mesh，只修正相机半径并把MoviePy原始视频规范为精确61帧；H.264、yuv420p、768×576和30 fps均通过检查。

正式机器记录为 `records/stage1_7_official_ldi_true_arc_v4.json`。

## 4. 自动诊断与人工门

端点三联图中，接近渲染背景灰色 `[128,128,128]`（逐通道容差3）的像素占比为：

| 帧 | 灰色背景占比 |
|---|---:|
| 左端 -15° | 27.81% |
| 中心 0° | 0.51% |
| 右端 +15° | 26.81% |

该统计说明端点存在大面积 mesh 未覆盖区，但不替代视觉评阅。人工评阅一次性记录：

1. 左端空洞/未覆盖严重度（0无、1轻微、2明显、3严重）；
2. 右端空洞/未覆盖严重度（0–3）；
3. 拉伸或虚假结构严重度（0–3，以更差端点为准）；
4. 运动连续性是否可接受；
5. 总体是否通过30°质量门。

任一端空洞严重度≥2、拉伸/虚假结构≥2、运动不连续或总体不可接受，均判为不通过。人工结论写入前不扩展P02/P05、不转换为补充高斯。

## 5. 用户人工结论与阶段决定（2026-08-14）

- 左端空洞/未覆盖严重度：`3`；
- 右端空洞/未覆盖严重度：`3`；
- 拉伸或虚假结构严重度：`2`；
- 运动连续性：尚可；
- 总体结论：不通过。

完整 LDI 的显式连通与逐层补全保持了尚可的时间连续性，但没有覆盖总范围30°端点所需的大面积新视野，且已有补入/拉伸内容仍达到不可接受门槛。正式人工记录为 `records/stage1_7_official_ldi_true_arc_v4_manual_review.json`。

**停止项**：不通过扩大外推厚度、改灰底、裁剪或缩小画面来隐藏空洞；不继续调官方3D Photo参数；不扩展P02/P05；不转换为补充高斯。

**下一方向**：把目标相机本身作为生成条件，使模型直接回答“这个指定±15°视角应看见什么”，并把中心视锥外区域交给显式 `OutsideFOVProvider`，不再假设源视锥内LDI外推可以独自覆盖30°。
