# 总体 Framework 讨论总结：自适应、可补全的轻量 3DGS

## 1. 总体路线

最终核心表示继续采用 3DGS，不把 3DGS 只作为教师或中间结果。

总体目标是：以 SHARP 的单图前馈 3DGS 为基础，增加场景感知、显露区域补充高斯、自适应高斯保留、材质表达和移动端压缩渲染能力。

```text
单张 RGB 图像
→ 场景感知
→ SHARP 式基础高斯
→ 显露区域补充高斯与双侧锚点
→ 基础高斯和补充高斯融合
→ 高斯剪枝、合并与量化
→ 移动端 3DGS 渲染
```

当前已经跑通的是 SHARP 基线。场景感知、多任务输出、补充高斯、可学习 Gate 和移动端渲染仍属于待实现方案。

## 2. 共享编码器与五类场景感知输出

把 Depth Pro 拆成特征编码器和深度解码器后，共享编码器本身只输出多尺度特征图 `F1～F4`，不会直接输出五类结果。

应在共享特征后增加多个轻量任务 Head：

```text
RGB → Depth Pro 共享编码器 → F1、F2、F3、F4
                              ├→ 深度解码器 → 两层视差/深度
                              ├→ 边界 Head → 深度边界
                              ├→ 细结构 Head → Alpha 与细结构概率
                              ├→ 材质 Head → 材质类别概率
                              └→ 置信度 Head → 预测可靠程度
```

五类输出的作用：

- 基础深度：决定基础高斯的三维位置。
- 深度边界：判断前后景切换和可能显露的位置。
- Alpha/细结构：保护头发、花茎、栏杆、辐条等区域。
- 材质类别：判断是否需要视角相关外观能力。
- 置信度：决定是否保守处理、减少剪枝或限制视角范围。

五类输出是五种信息，不等于只有五个通道。例如两层视差占 2 个通道，材质类别可能占 4 个通道。

### 2.1 从共享特征到高斯剪枝的完整数据流

整体方向不是“四张特征图分别进入四个解码器”，也不是“所有场景感知结果都直接输入高斯初始化器”。更准确的结构是：同一组多尺度特征被多个任务分支共同复用，再由不同模块使用各分支的输出。

```text
输入 RGB
→ Depth Pro 特征编码器
→ 输出四级多尺度特征 F1、F2、F3、F4
→ 同一组 F1～F4 分别被多个任务解码器复用
```

`F1～F4` 具有不同分辨率和语义层次。每个解码器通常会融合多级特征，而不是一个特征图只对应一个解码器。

#### （1）四类解码分支

```text
共享的 F1～F4
├→ 深度解码器
│    ├→ 第一层视差
│    └→ 第二层视差
│
├→ 边界与细结构解码器
│    ├→ 深度边缘图 E
│    ├→ Alpha 图 A
│    └→ 细结构概率图 T
│
├→ 材质解码器
│    └→ 材质类别概率 M
│
└→ 置信度解码器
     └→ 深度置信度 C
```

- `Alpha A` 描述像素的前景覆盖程度、软边界或半透明程度。
- `细结构概率 T` 判断该位置是否属于花茎、发丝、栏杆或辐条等细结构。
- Alpha 与细结构概率不能合并为同一个概念。
- `深度置信度 C` 描述模型对当前深度判断的可靠程度。

#### （2）SHARP 基础高斯初始化

高斯初始化器的核心输入仍然是 RGB 和两层视差：

```text
RGB + 两层视差
→ SHARP 几何初始化器
→ 每个网格位置初始化两层候选高斯
```

两层视差主要用于确定高斯的空间位置，初始化器同时给出基础颜色、尺度、旋转和不透明度。深度边缘、Alpha、细结构、材质和置信度不必全部塞入几何初始化器，而是用于后续的重要性判断、局部增密、材质外观和显露补全等模块。

#### （3）Importance/Gate Head

将共享特征和场景感知结果输入一个轻量的重要性预测网络：

```text
共享特征
+ 两层视差
+ 深度边缘 E
+ Alpha A
+ 细结构概率 T
+ 材质概率 M
+ 深度置信度 C
→ Importance/Gate Head
→ 两层 Gate：[B, 2, 768, 768]
```

这里暂时不称为“密度图”，因为该输出不能直接决定每个位置生成几个整数高斯。它表示的是：已经初始化出来的每个候选高斯应该保留到什么程度。

两个 Gate 通道分别控制第一层基础高斯和第二层遮挡/背景候选高斯。

#### （4）训练阶段的软 Gate

SHARP 仍然生成固定数量的候选高斯，Gate 只控制每个高斯的有效渲染贡献：

```text
有效不透明度
= Gaussian Decoder 预测的不透明度 × Gate
```

典型结果应为：

- 平坦天空等冗余区域的 Gate 接近 0。
- 普通物体表面的 Gate 保持中等或较高。
- 花茎、发丝和栏杆等细结构区域的 Gate 接近 1。
- 遮挡边界后的第二层高斯，根据其在侧视角中是否有贡献决定 Gate。

训练时只是让部分高斯近似关闭，候选高斯的张量数量并未改变，因此该过程可以反向传播。

#### （5）训练完成后的硬剪枝

训练完成后，再根据多项信息真正删除高斯：

```text
Gate 分数
+ 高斯最终 Opacity
+ 多视角实际渲染贡献
→ 低于阈值
→ 硬剪枝
```

这里需要区分三种概念：

- 场景感知的 `Alpha A`：描述图像前景覆盖和软边界。
- 高斯自身的 `Opacity`：描述该高斯的渲染贡献。
- `Gate`：描述该高斯是否值得保留。

因此，更合理的剪枝依据是：

```text
剪枝重要性 = Gate × Gaussian Opacity × 多视角贡献
```

Alpha 和细结构概率主要作为 Gate Head 的判断依据，而不是直接作为最终剪枝阈值。

#### （6）当前方案的能力边界

第一阶段方案的本质是：

```text
固定生成约 118 万个候选高斯
→ 学习哪些候选高斯应该保留
→ 训练完成后删除冗余高斯
```

这能实现自适应保留和剪枝，但不能让细结构区域突破 SHARP 原有的候选数量上限。若要实现真正的动态密度分配，还需要增加：

```text
细结构区域或高误差区域
→ Split/Spawn
→ 生成额外、更小的高斯
```

因此，该部分的完整思路可概括为：

> 输入图像经过共享编码器和多个任务解码器，得到两层视差及场景感知信息；两层视差用于建立 SHARP 基础候选高斯，其他信息由轻量 Gate Head 汇总，预测两层候选高斯的重要性；训练时使用软 Gate 控制渲染贡献，训练完成后结合 Gate、高斯不透明度和多视角贡献执行硬剪枝，后续再通过 Split/Spawn 为细结构和高误差区域补充额外高斯。


### 2.2 从基础高斯到最终轻量高斯的端到端流程

完整方案可以理解为“先建立基础表示，再分别学习做减法和做加法，最后统一渲染、训练和压缩”。

#### （1）基础高斯生成

```text
输入 RGB
→ 共享特征编码器
→ 多尺度特征 F1、F2、F3、F4
→ 深度解码器输出两层视差
```

基础高斯并不只由 RGB 和深度直接决定：

```text
RGB + 两层视差
→ SHARP Initializer
→ 固定双层候选高斯 Base

RGB + 两层视差 + F1～F4
→ Gaussian Decoder
→ 高斯属性修正 Delta

Base + Delta
→ 基础高斯 G_base
```

Initializer 负责建立规则几何初值，Gaussian Decoder 再利用共享特征修正位置、尺度、旋转、颜色和不透明度。

#### （2）两条自适应控制分支

第一条分支负责对已有高斯做减法：

```text
共享特征
+ 两层视差
+ 深度边缘
+ Alpha
+ 细结构概率
+ 材质类别
+ 深度置信度
→ Keep/Gate Head
→ 判断基础候选高斯保留到什么程度
```

第二条分支负责发现哪里缺少高斯。它不能只看编码特征，还要先用基础高斯试渲染浅 3D 范围内的左右端点：

```text
G_base
→ 左右端点试渲染
→ 目标视角 RGB、Depth、Alpha
→ 联合共享特征、边缘、细结构和置信度
→ 检测空洞、拉伸、遮挡错误和细结构断裂
```

#### （3）增加高斯的两种方式

```text
Split：已有表面表示过粗
→ 将较大高斯拆成多个更小高斯
→ 用于花茎、发丝、栏杆和辐条等细结构

Spawn/Completion：侧视角出现新的隐藏表面
→ 补全深度边缘
→ 补全 Depth
→ 补全 RGB、Alpha 和置信度
→ 反投影为显露区域补充高斯
```

因此，自适应高斯分配不是只有 Gate：

```text
自适应高斯分配
= Keep/Gate 自适应删减
+ Split 细结构局部增密
+ Spawn/Completion 显露区域补充
```

#### （4）统一候选池与共同渲染

```text
基础高斯 G_base
+ 细结构高斯 G_split
+ 显露补充高斯 G_supp
→ 统一候选高斯 G_all
```

所有候选高斯进入同一坐标系和同一套 3DGS 渲染器，在中心、左右端点和中间视角共同渲染，而不是分开输出三套场景。

训练损失可以包括：

```text
RGB / DISTS / LPIPS
+ 深度与 Alpha 一致性
+ 左右端点锚点损失
+ 中间视角连续性
+ 细结构局部损失
+ Gate 稀疏与高斯数量预算
```

这些损失共同调整基础高斯属性、Keep Gate、Split 位置、显露补全结果和补充高斯属性。

#### （5）推荐的分阶段训练

不建议一开始让所有模块同时变化，否则 Spawn、Gate 和 Gaussian Decoder 可能互相抵消。更稳妥的顺序是：

```text
阶段一：冻结 SHARP 主体，训练 Keep/Gate
阶段二：训练显露补全与补充高斯
阶段三：加入细结构 Split/Spawn
阶段四：使用较小学习率联合微调
```

#### （6）推理与最终硬剪枝

模型训练完成后，每张输入图像都会生成自己的基础、细结构和显露补充候选高斯。推理时先合并候选，再根据预定浅 3D 视角范围估计多视角贡献：

```text
高斯重要性
= Gate × Gaussian Opacity × 多视角实际贡献
```

然后执行：

```text
低重要性高斯 → 删除
位置与外观接近的高斯 → 合并
剩余高斯属性 → 量化
→ 导出该输入图像对应的最终轻量 3DGS
```

这一流程可概括为：

> 输入图像先生成 SHARP 基础高斯；场景感知信息一路进入 Gate Head，对已有高斯做减法，另一路结合左右端点试渲染结果，通过 Split 或 RGB-D-Alpha 补全增加细结构和显露高斯；全部候选高斯在统一场景中共同渲染并计算多视角损失，模型训练完成后，每张图在推理和导出阶段依据 Gate、Opacity 与多视角贡献执行统一硬剪枝、合并和量化。
## 3. SLIDE 对细结构处理的启发

SLIDE 的基础软分层根据深度梯度降低遮挡边界处的前景可见性，但深度图经常无法保留细头发。

SLIDE with Matte 额外采用：

```text
RGB
→ U²-Net 前景分割
→ FBA Matting
→ 前景 Alpha Matte
→ 与深度边界和遮挡图结合
→ 最终前景可见性
```

它不是直接把 Alpha 当作可见性，而是通过膨胀等操作提取前景轮廓附近的软边界带，再与深度产生的可见性结合。这样能够在新视角中保留头发和毛发等半透明细节。

这一方法主要保护显著前景轮廓，不保证覆盖背景栏杆、树枝或所有细线结构。

## 4. 我们的轻量细结构 Head

不建议在部署时完整串联 Depth Pro、U²-Net 和 FBA Matting。更适合的做法是复用 Depth Pro 多尺度特征，增加一个轻量 FPN/简化 U-Net 解码器。

```text
F4 上采样并与 F3 融合
→ 与 F2 融合
→ 与 F1 和 RGB 浅层细节融合
→ Alpha Head：输出前景覆盖比例
→ Thin Structure Head：输出细结构概率
```

建议同时输出两张图：

- `Alpha A`：表示前景覆盖比例和软边界。
- `Thin T`：表示该位置是否属于花茎、头发、栏杆等细结构。

Alpha 和细结构不能混为一谈。人物衣服内部和不透明花茎的 Alpha 都可能接近 1，但只有花茎需要更高高斯密度。

训练时可以使用 U²-Net 与 FBA Matting 生成 Alpha 伪标签，把重型 Matting 能力蒸馏到共享编码器后的轻量 Head 中。

## 5. SHARP 的 Gaussian Initializer

SHARP 的 `MultiLayerInitializer` 不是神经网络，而是一套不可学习的几何规则。

输入为：

```text
RGB 图像：[B, 3, 1536, 1536]
两层深度：[B, 2, 1536, 1536]
```

默认输出为两层 `768×768` 基础高斯，因此总候选数约为：

```text
2 × 768 × 768 = 1,179,648
```

基础高斯属性的初始化方式：

- x、y：规则 NDC 网格坐标。
- z：来自两层逆深度/视差。
- 尺度：与深度成正比，近处小、远处大。
- 旋转：单位四元数，使用默认朝向。
- 颜色：发布配置中两层都复制降采样后的输入 RGB。
- 不透明度：两层均从 0.5 开始。

初始化器还将 `RGB 3 通道 + 两层视差 2 通道` 拼成 5 通道输入，送给 Gaussian Decoder。Gaussian Decoder 再结合 Depth Pro 的 `F1～F4` 预测位置、尺度、旋转、颜色和不透明度修正量，Composer 将基础值与修正量组合为最终高斯。

## 6. SHARP 如何隐式处理额外内容

SHARP 没有独立的“显露区域补充高斯”模块，也不会根据目标视角重新生成高斯。

它在每个网格位置固定生成两层候选高斯，并通过新视角渲染损失，让第二层深度、颜色、透明度和属性修正在训练中隐式学习遮挡与显露能力。

第二层不能简单等同于真实隐藏背景：发布模型不强制两层近远排序，输入图也没有完整隐藏内容真值。小视角时，两层高斯、椭球覆盖和透明度混合可以遮盖少量缺口；视角扩大后，固定两层容易出现空洞、拖影和错误显露。

## 7. 新增的显露区域补充高斯

新 Framework 将 SHARP 隐式学习的显露能力进一步显式化：

```text
SHARP 基础高斯
→ 渲染目标视角范围
→ 找到低 Alpha、空洞和错误显露区域
→ 联合补全 RGB、Depth、Alpha
→ 将补全结果反投影为补充高斯
→ 使用左右目标视角端点约束
→ 与基础高斯融合并去重
```

基础高斯表示输入图已经看见的内容；补充高斯表示相机移动后可能露出的内容。双侧锚点提高的是结果一致性，不能提供单图中不存在的真实隐藏证据。

## 8. Density/Importance Head 与软 Gate

第一版不直接生成可变整数数量高斯，而是保留 SHARP 的固定候选网格，为每个候选高斯预测保留概率。

更准确的名称是“场景感知引导的重要性预测与软剪枝”，而不是完整动态密度分配。

由于 SHARP 每个位置有两层高斯，建议输出：

```text
Gate：[B, 2, 768, 768]
```

两个通道分别控制第一层和第二层候选高斯。单通道 Gate 会迫使两层同时保留或删除，不符合实际需求。

推荐输入：

```text
Depth Pro 解码特征
+ 两层视差
+ 深度边界
+ Alpha 边界
+ 细结构概率
+ 材质 logits
+ 置信度
```

推荐使用轻量 Head：

```text
1×1 Conv
→ Depthwise 3×3 Conv
→ 1×1 Conv
→ 高分辨率跳接
→ 2 通道 Gate
→ Sigmoid
```

使用深度可分离卷积时，参数量约 2 万，可以忽略不计。

## 9. Importance 与 Gate 的含义

- Importance：每个高斯“有多值得保留”的分数。
- Gate：将这个分数作为连续开关使用。

第一版中，两者可以使用同一个输出：

```text
特征 → Gate Head → Sigmoid → g∈[0,1]
```

训练时使用软 Gate：

```text
effective_opacity = predicted_opacity × gate
```

Gate 接近 0 时，高斯几乎不参与渲染；Gate 接近 1 时，高斯基本完整保留。连续 Gate 可反向传播，避免训练时直接执行不可微的整数删除。

训练完成后再硬剪枝：

```text
Gate 或多视角贡献低于阈值
→ 真正从 PLY/移动端资源中删除
```

训练时的软 Gate 只模拟关闭，导出时硬剪枝才会真正减少文件大小、内存和渲染计算量。

## 10. Gate 的训练信号

Gate 没有直接真值，主要由两股力量共同训练：

1. 渲染与感知损失：RGB、DISTS、LPIPS 和跨视角一致性要求关键高斯保持开启。
2. 稀疏或预算损失：鼓励关闭不重要高斯，避免所有 Gate 都退化为 1。

```text
总损失
= RGB / DISTS / LPIPS
+ 多视角一致性
+ 细结构局部损失
+ Gate 稀疏或目标预算损失
```

建议先冻结原 SHARP 主体，只训练 Gate Head，避免 Gaussian Decoder 通过增大 Opacity 抵消 Gate；Gate 稳定后再用较小学习率联合微调。

Gate 必须使用中心、左右端点和中间视角共同训练。只使用中心视角会把当前被遮挡、但侧面视角有用的第二层高斯误删。

## 11. 需要修正的“密度图”理解

当前 Gate 方法只能从固定候选中删除，不能让细结构区域拥有超过 SHARP 原始上限的更多高斯。

因此完整的自适应高斯分配需要两步：

```text
第一步：Gate 关闭简单区域的冗余高斯
第二步：Split/Spawn 在细结构和显露区域增加小高斯
```

复杂材质也不一定需要更多高斯，它主要需要更合适的视角相关外观。高斯数量控制和外观复杂度控制应当分开设计。

“从 118 万压缩到 30～50 万”目前只能作为实验目标，不能作为已得到的结论。最终数量需要通过 100%、75%、50%、25% 等保留率实验确定。

## 12. 推荐实施顺序

```text
1. 完成 SHARP 基线结论和规则剪枝摸底
2. 增加两层 Gate Head，训练场景感知引导的软剪枝
3. 实现显露 RGB-D-Alpha 补全和补充高斯
4. 加入双侧目标视角锚点
5. 在细结构或高误差区域增加 Split/Spawn 高斯
6. 对基础、补充和细分高斯统一剪枝、合并与量化
7. 最后增加材质外观和移动端渲染
```

当前先对原始 SHARP 做剪枝实验仍然有价值，它用于摸清冗余量和预算；但最终压缩参数必须在补充高斯和细分高斯加入后重新确定。

## 13. 核心结论

```text
SHARP：固定两层、固定网格的候选高斯 + 学习属性修正

第一阶段改进：场景感知输出 → 两层 Importance/Gate → 软剪枝 → 硬剪枝

完整改进：软剪枝 + 细结构 Split/Spawn + 显露区域补充高斯
             ↓
          统一压缩
             ↓
       轻量移动端 3DGS
```

最稳妥的第一版是不破坏 SHARP 的固定张量结构，只增加轻量两层 Gate Head；验证可学习剪枝有效后，再逐步增加细结构高斯和显露补充高斯。

## 14. 30° 显露补全优先版（2026-08-05 修订）

### 14.1 冻结目标

- 输入：单张 RGB；

Gate 是"做减法"，只能删除已有高斯；30° 最大的问题是原图看不到的区域根本没有内容，必须先验证"做加法"。因此质量路线（显露补全 + 补充高斯）先于压缩路线（Gate/剪枝/合并/量化），等 30° 质量成立后再研究变小变快。

### 14.11 补全模型选型（2026-08-05 补充）

补全主线按"静态大缺口补全"设计，视频时序一致性另作诊断分支，不混入主线：

- **LaMa**：静态大缺口补全基线（Stage 1 起步）；
- **MAT**：更强的单图大缺口补全模型，与 LaMa 公平比较；
- **ProPainter**：面向视频修复（前后帧信息传播 + 时空 Transformer），定位为视频后处理与帧间时序一致性**诊断分支**，不作为单图补全主线的直接替代。

原因：当前 60 帧视频都来自同一个不完整的 SHARP 场景，没有真正新增被遮挡区域的信息。ProPainter 能减少帧间闪烁、让纹理在帧间更连续、填补部分视觉空洞，但不能真正恢复可靠的三维结构；把视频补全结果直接转成高斯容易出现跨视角内容不一致、纹理漂移/拉伸、补全区域深度缺失和"贴纸感"，只在视频层面有效。

最终正式方案不变：补全结果必须转成 RGB-D-Alpha，再生成补充高斯。

最小诊断实验（可选）：SHARP 60 帧结果 → 逐帧缺口掩码 → ProPainter 补全 → 比较补全前后视频。评价重点：缺口覆盖率、帧间闪烁、边缘连续性、视角端点结构合理性、能否稳定转成补充高斯。

一句话：LaMa/MAT 解决"单张图缺什么内容"，ProPainter 解决"视频中各帧如何保持一致"；ProPainter 只作辅助实验分支，不替代当前单图补全主线。

### 14.14 Stage 1.3 Canonical Layer Bundle（当前主协议）

隐藏内容统一使用 Canonical Layer Bundle（CLB）进入后续管线。CLB 区分三类表面：中心真实观测表面、中心射线上的遮挡后方表面，以及中心视锥外但会在 ±15° 进入画面的扩展表面。这一区分弥补了仅以中心视角 LDI 表达 P01 外侧大缺口的不足。

每个表面块必须携带 RGB、Z-depth、Alpha、有效掩码、逐像素来源、几何置信度和外观置信度。置信度不等于 Alpha/Opacity；所有预测内容必须先通过深度顺序、中心泄漏、端点重投影和跨视角冲突门，才允许进入 Gaussian Spawn。旧 `stage1_build_supplement_gaussians.py` 只能作为 legacy 实验工具，未适配 CLB 前不得用于新主线。

首个候选不是再接一个预训练补全网络，而是 `CLB-SYN-01` 受控合成表示能力实验：同时构造遮挡后方层与左右视锥外扩展层，先确认它们能在中心不泄漏、在 ±15° 正确显露。表示层硬门通过后才实现 `CLB → supplemental Gaussians`，然后再审计可接入的隐藏层预测模型。详细协议见 `03_实验记录/自研Framework实验/01_Stage0_1_角度与显露补全/Stage1_3_隐藏层表示与验证协议.md`。

`CLB-SYN-01` 表示层和 `CLB-GS-SYN-01` v2 高斯转换层已于2026-08-13分别通过受控合成硬门。高斯转换不使用端点角度渐入，证明共享世界坐标与几何可见性足以表达遮挡后方和中心视锥外两类隐藏表面。这是表示能力结论，不是单图预测或 P01 30° 质量结论。当前瓶颈已前移到 `HiddenLayerProvider`：下一阶段先在有多视图真值的小数据上评估隐藏几何、外观和置信度预测，不用无真值 P01 直接选模型。

### 14.15 Stage 1.4 Provider 拆分与双真值评价（已完成）

`HiddenLayerProvider` 进一步拆成 `OcclusionHiddenProvider` 与 `OutsideFOVProvider`。这个拆分是能力边界，不是实现细节：Flash3D/MINE 一类源视锥内层式模型只能生成同一中心视锥内的遮挡后表面，不能凭自身覆盖中心原图外的世界；后者必须由独立 Provider 负责，最后再进入同一 CLBValidator 与 SurfaceFusion。

首个 `OcclusionHiddenProvider` 候选为 Flash3D `re10k_v2`。它原生每像素输出两层累计深度与高斯属性，适配 CLB 的路径较短；但官方 opacity 只属于渲染参数，不是独立置信度，适配器必须新增可校准的 geometry/appearance confidence，并把视锥外支持明确标为 unsupported。`OutsideFOVProvider` 暂不选择，禁止用 Flash3D 边缘复制或不受控外推临时代替。

评价采用双数据集：`HLP-APP-01` 从 RealEstate10K 的官方 Flash3D 验证序列中按真实相机姿态筛 `-15°/0°/+15°` 三元组，只评价目标 RGB与新视角外观；`HLP-GEO-01` 从 Hypersim test split 中选极小子集，用 RGB、逐像素距离/世界位置、相机位姿和内参评价隐藏几何、深度顺序与支持区。RealEstate10K 没有稠密深度，不允许用 RGB 指标代替几何真值；Hypersim 全量约1.9TB，只允许元数据优先、选中文件按需下载。

Flash3D checkpoint/源码结构静态预检、RTX 5080 推理、RealEstate10K 外观 A/B 与 Hypersim 稠密几何评价均已完成。双层相对单层通常改善外观，但原始米制遮挡后几何平均 AbsRel 为23.33%、δ<1.10为24.80%；使用源深度真值做不可部署的 oracle 尺度对齐后仍为18.17%/39.50%。高 opacity/alpha 也不稳定对应低几何误差，因此不把它冒充 confidence。Flash3D 原样不通过 `OcclusionHiddenProvider`，固化为参考基线，不接 P01、不继续针对它调参。详细证据见 `03_实验记录/自研Framework实验/01_Stage0_1_角度与显露补全/Stage1_4_HiddenLayerProvider候选与双真值协议.md`。

### 14.16 Stage 1.5 自研 Provider 骨架（已完成）

可复用核心代码位于 `源码/Adaptive3DGS/`。第一版已经把 `OcclusionHiddenProvider`、`OutsideFOVProvider`、Provider 注册器、CLB 数据类、部署前验证器、安全 manifest/NPZ I/O，以及模型无关的遮挡后几何/置信度 evaluator 落实为独立 Python 包。HLP-GEO 数据/相机适配层也已接入：默认不向 Provider 暴露源深度真值，3场景、6目标的60项真实数据门全部通过，并准确复现冻结的遮挡后/视锥外掩码统计。Flash3D 只读映射层将第二层规范为未校准 CLB，并将原生目标渲染规范为统一几何预测；Alpha 只作支持概率，confidence 固定为0。当前15项单元测试通过；Stage 1.3 合成 bundle 的61项逐元素 round-trip 门和旧验证器交叉检查也全部通过。

### 14.17 Stage 1.6 独立训练监督（已完成，候选未通过）

首个自研 Provider 的数据边界已经冻结：Hypersim 官方 train/val 用于训练与选择，HLP-GEO-01三个官方 test 场景只在候选冻结后评价，P01不参与训练或调参。首批管线冒烟使用8个train、2个val场景，均按真实相机旋转选出总范围30°三元组；130个必要文件通过Range定向获取，没有下载完整场景ZIP。

目标视角first-hit RGB-D只能提供源射线后方表面的正证据，未覆盖源射线不能当作隐藏层不存在。因此核心监督生成器只输出`positive + unknown`：候选必须同时深于源first hit 1 cm与1%，同一源像素保留最近后方表面并记录观测数/深度跨度。canonical v2在10个三元组上产生912,897个正证据像素，最弱场景仍有1.6127%，50项门全部通过。为保留验证场景，核心还加入一般Hypersim投影的RQ分解，可将倾斜传感器分解为上三角K与相机旋转修正。

三头网络已经实现正深度增量、support probability和独立geometry confidence，并加入相机射线、/16上下文、delta-conditioned头与目标视角verified free-space负证据；unknown始终不伪装成负类。实现合同30/30测试通过，单样本几何与support过拟合也通过。

随后依次完成8 train/2 val单帧、相同8/2场景的80/20多源帧，以及40 train/10 val独立场景的场景多样化候选。最终HLP-TRAIN-03在1000次更新后，val ratio AbsRel从3.8958降到2.3451，但support正例/verified-negative分离仅0.02204，未达到冻结0.05门；训练集分离也只有0.02456。候选正式未通过，且按协议未读取HLP-GEO test、未接P01。

该结果将问题边界从“监督或代码是否可学习”缩小为“source-only小型网络对隐藏表面存在性的跨场景可辨识性不足”。下一候选不再只调整优化器或横向更换二维补全器，而改变信息结构：先验证具有显式像素连通和逐层合成的完整LDI管线，必要时再转向显式目标视角条件化Provider。`OutsideFOVProvider`继续独立，不与本阶段混写。

### 14.18 Stage 1.7 完整 LDI 候选（已完成，人工不通过）

官方3D Photo完整LDI链路已在P01上跑通。它不是此前固定端点三网络adapter：本轮实际建立显式像素连通，按深度断边形成局部遮挡组件，迭代补全边缘、深度与颜色，再导出多层mesh。为了保持项目单变量边界，深度使用冻结P01中心深度，焦距使用实测3195.073 px，渲染使用无裁剪61帧`true_arc`总范围30°；官方源码保持固定commit且未修改。

canonical v4自动诊断显示-15°/+15°端点分别有27.81%/26.81%的灰色未覆盖区，三联图还可见树木和栏杆边缘拉伸。用户完整播放后评分为空洞严重度3/3、拉伸或虚假结构2、运动连续性尚可、总体不通过。显式LDI改善了部分遮挡后内容和时间连续性，却没有解决30°所需的大范围中心视锥外内容。

因此完整LDI冻结为结构化失败基线，不通过扩大外推、裁剪或改背景掩盖问题，不扩展P02/P05，也不转补充高斯。下一阶段必须把目标相机作为显式条件，让Provider面向指定±15°视角生成/重建新显露内容，并将中心视锥外区域交给一级`OutsideFOVProvider`；不能继续假设source-only隐藏层或有限边界外推能独自满足30°。
