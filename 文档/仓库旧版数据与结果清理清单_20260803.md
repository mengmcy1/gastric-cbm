## 1. 清理目标与当前空间

后续项目将基于新数据重新完成分类、定位、MOCE和SAE，因此旧版大体积图片和中间输出
可以分阶段退出活动目录。但清理不能破坏旧实验的追溯能力，也不能把“已发给医学生”
直接等同于“已有可靠备份”。

当前空间快照：

| 项目 | 占用 |
| --- | ---: |
| 服务器分区 | 915G |
| 已使用 | 623G（72%） |
| 可用 | 246G |
| `gastric-cbm`仓库 | 56G |
| `结果/` | 45G |
| `数据/` | 9.2G |
| `发布资产/` | 1.2G |

当前磁盘没有紧急压力。本清单应在新数据逐步到位后按阶段执行，不建议一次性批量删除。

## 2. 清理等级

- **A：可优先清理**：重复副本、debug、缓存或随时可重新打包的文件。
- **B：确认交付后可清理**：已经形成正式提交版，原始全量渲染可由脚本重新生成。
- **C：新流程达到门槛后清理**：当前仍承担旧基线、对照或解释流程追溯作用。
- **D：只允许外迁归档**：不可替代的原始数据、人工整理数据或隐私资产，不直接删除。
- **E：继续保留**：新流程仍需要的数据、正式文档、冻结清单和外部测试集。

## 8. 每次实际清理前的检查

每一批删除或迁移前都执行以下检查：

- [ ] `git status`干净，确认没有用户未提交修改。
- [ ] 没有相关训练、投影、分析或复制进程正在运行。
- [ ] 记录待处理目录的文件数和总大小。
- [ ] 对不可替代资产生成SHA256清单，并在目标存储验证。
- [ ] 确认正式CSV、JSON、config、manifest、权重和阅读指南不在待删除范围。
- [ ] 搜索代码和文档中的绝对路径引用。
- [ ] 迁移后先运行最小读取测试，再处理原目录。
- [ ] 更新`数据/README.md`、`结果/README.md`及相关正式文档中的路径。
- [ ] 若历史归档改为仓库外保存，同步更新`AGENTS.md`中的长期保存规则和归档位置。
- [ ] 记录实际释放空间、执行日期和执行人。
