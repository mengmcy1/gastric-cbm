# RP-A-lite 探索性稳定性筛查（2026-08-25）

## 一、阶段定位

本阶段是在正式 RP-A 因 bootstrap 计算成本和 CUDA 长 kernel 超时而未完成后，新增的一条独立、限时的探索性路线。目的不是改写或替代已经冻结的正式 RP-A 协议，而是尽快回答一个更小的问题：

> seed42、43、44 三套 SAE 字典之间，是否已经存在足够稳定的跨初始化 Feature 结构，值得继续制作医生可读的概念材料？

本阶段不产生正式 RP-A PASS/FAIL，不修改冻结协议，也不把结果写回正式 bootstrap 记录。

## 二、执行边界

- 固定使用 bootstrap replicate `0..99`，共 100 次；选择发生在结果查看前。
- 沿用正式 RP-A 的患者分层有放回抽样、完整重匹配、最弱伪确认折归约和六项指标定义。
- cutoff 仍由每项最弱折分布的第 5 百分位产生，使用 `numpy.quantile(method="lower")`。
- 只读复用第一次 RP-A development 的 seed42/43/44 train analysis cache 和已完成记录。
- 第一次运行在 `0..99` 中已有 85 条，本阶段只重算缺失的 15 条；索引为 `56,59,...,98`。
- 第一次运行中索引大于等于 100 的 75 条记录不进入本次分析，避免按“先完成的任务”事后选择样本。
- 不运行 val reproduction，不运行 seed202/503/911，不读取 internal test 或 external。
- 本阶段得到的数值统一称为“探索性 cutoff”，不得称为正式 RP-A threshold。

## 三、工程恢复与数值一致性

首次 Lite 补算使用 `source_block=32, target_block=128`。replicate 56 完成后，另一条复杂 replicate 仍触发 CUDA launch timeout，因此保留现场并停止，没有生成汇总结论。

恢复时仅把 target 分块进一步缩小为 64。分块只改变一次送入 GPU kernel 的目标 Feature 数，不减少候选 Feature、不改变匹配空间和统计公式。恢复前使用 replicate 53 做逐项等价性检查：

| 对照 | 三折六指标最大绝对差 |
|---|---:|
| `32x256` vs `32x128` | 0.0 |
| `32x256` vs `32x64` | 0.0 |

因此 128 和 64 两种工程分块与第一次正式实现的 256 分块在该完整 replicate 上逐位一致。本阶段最终由 85 条旧记录、首次补算的 replicate 56 和恢复补算的其余 14 条组成。

## 四、探索性结果

seed42/43/44 完整 train matching 得到：

- eligible Feature：9418 / 9420 / 9406；
- pair edges：1262 / 1256 / 1270；
- strict 3-clique anchors：1150，明显高于冻结的最低可行规模 100。

100 次 bootstrap 产生的探索性 cutoff，以及完整 train 三个伪确认折中的最弱值如下：

| 指标 | 探索性 cutoff | 完整 train 最弱折 | 探索性比较 |
|---|---:|---:|---|
| Anchor recall | 0.893987 | 0.905512 | 高于 cutoff |
| Confirmation coverage | 0.119605 | 0.122081 | 高于 cutoff |
| Activation reference | 0.934600 | 0.939612 | 高于 cutoff |
| Activation confirmation | 0.754458 | 0.762470 | 高于 cutoff |
| Energy reference | 0.961546 | 0.967329 | 高于 cutoff |
| Energy confirmation | 0.883126 | 0.889341 | 高于 cutoff |

六项均高于各自的探索性 cutoff。也就是说，在当前 train-only、B100 的快速稳定性筛查中，三套不同初始化的 SAE 字典形成了数量充足、患者行为和表示能量均较稳定的跨 seed Feature 对应关系。

## 五、结果如何理解

这个结果支持：

1. C-long 学生内部并非只有偶然、单 seed 才出现的 SAE Feature；不同 SAE 初始化之间存在可重复结构。
2. 1150 个 strict anchors 是后续构建 Feature family 和医生复核候选的充足技术池。
3. 患者激活行为与表示能量两侧均通过探索性筛查，说明匹配并不只依赖 decoder 方向相似。
4. 现在值得进入“概念是否可读、是否涉及癌与非癌共享模式、是否真正影响模型决策”的解释阶段。

这个结果不支持：

1. 不能宣布正式 RP-A 通过；正式协议要求 B400 和 val reproduction，本阶段都未完成。
2. 不能把 1150 个 anchors 等同于 1150 个医学概念；多个 Feature 可能属于同一概念家族，也可能是纹理、反光、器械或来源风格。
3. 不能宣布跨模型确认成功；seed202/503 尚未运行。
4. 不能用本结果评价 internal test 或 external 泛化。

## 六、下一步

在时间优先的前提下，下一步不再继续扩充 Lite bootstrap，而是从 1150 个 development strict anchors 中建立医生可读候选：

1. 按跨 seed 一致性、患者覆盖、癌/非癌分布和表示能量进行技术排序，但不删除癌与非癌共享 Feature。
2. 为候选 Feature 导出高、中、低、零激活图，以及外观相似但不激活的反例。
3. 单独标记病灶相关、正常黏膜、反光、气泡、器械和来源风格等候选解释。
4. 把癌侧偏高、非癌侧偏高和癌/非癌共享 Feature 分开报告；共享 Feature 保留用于判断其是否是基础黏膜结构或共同视觉模式。
5. 在医生命名前先做 Feature/Feature-family 干预，区分“看起来像概念”和“模型实际依赖的概念”。

若后续时间和计算资源允许，正式 RP-A B400 与 val reproduction 仍应在独立正式运行中完成；Lite 结果不能补入或替代正式记录。
